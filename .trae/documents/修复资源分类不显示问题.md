# 修复资源分类缓存问题

## 问题确认

用户已经排查到根本原因：**缓存问题导致新添加的分类没有立即生效**

## 技术分析

当前系统使用了Redis缓存来存储字典数据：

- **缓存机制**：`SysDictDataServiceImpl.java`中的`selectDataByDictTypeCache`方法使用`@Cacheable(cacheNames = "sys_dict", key = "#dictType")`注解
- **问题点**：当在后台添加或修改字典数据时，缓存没有自动失效
- **影响**：前端调用`getDictDataApi('sys_resource_category')`时获取到的是缓存中的旧数据

## 修复方案

### 1. 添加缓存失效机制

**修改文件**：`blog/mojian-admin/src/main/java/com/mojian/service/impl/SysDictDataServiceImpl.java`

**修改内容**：

1. **在添加字典数据时清除缓存**：
   ```java
   @Override
   public void addDictData(SysDictData sysDictData) {
       save(sysDictData);
       // 清除对应字典类型的缓存
       SysDict dict = dictMapper.selectById(sysDictData.getDictId());
       if (dict != null) {
           cacheManager.getCache("sys_dict").evict(dict.getType());
       }
   }
   ```

2. **在修改字典数据时清除缓存**：
   ```java
   @Override
   public void updateDictData(SysDictData sysDictData) {
       updateById(sysDictData);
       // 清除对应字典类型的缓存
       SysDict dict = dictMapper.selectById(sysDictData.getDictId());
       if (dict != null) {
           cacheManager.getCache("sys_dict").evict(dict.getType());
       }
   }
   ```

3. **添加缓存管理器依赖**：
   ```java
   @Autowired
   private CacheManager cacheManager;
   ```

### 2. 优化SQL查询（可选）

**修改文件**：`blog/mojian-server/src/main/resources/mapper/SysDictDataMapper.xml`

**修改内容**：添加状态检查和排序

```xml
<select id="selectDataByDictType" resultType="com.mojian.entity.SysDictData">
    select sdd.*
    from sys_dict_data sdd
             left join sys_dict sd on sdd.dict_id = sd.id
    where sd.type = #{dictType}
    and sd.status = 1
    and sdd.status = 1
    order by sdd.sort asc
</select>
```

### 3. 临时解决方案

**对于当前已存在的缓存问题**：

1. **重启后端服务**：这会清除所有缓存，让新添加的分类生效
2. **手动清除Redis缓存**：如果有权限访问Redis，可以直接删除`sys_dict::sys_resource_category`缓存键

## 预期结果

修复后，当在后台添加或修改资源分类时：
1. 对应字典类型的缓存会自动失效
2. 前端再次调用API时会获取到最新的分类数据
3. 上传资源对话框中的分类下拉框会显示最新的分类列表

## 技术要点

- **缓存一致性**：确保数据修改与缓存更新的一致性
- **性能优化**：只清除相关字典类型的缓存，避免全量清除
- **可靠性**：添加空值检查，确保代码健壮性

此方案不仅解决当前问题，还能防止未来类似的缓存一致性问题。
